## Colour

There are **two different greens** in the supplied material. This needs a
decision before any design work.

### Declared palette — `brand/brand-palette-reference.jpeg`

The swatch the client sent, with hex values printed on it:

| Role | Hex | Note |
|---|---|---|
| Deep green | `#236147` | labelled on the swatch |
| Gold | `#B8943E` → `#C9A961` | shown as a gradient, no hex given; range sampled from the image |
| Cream | `#FFFEF4` | labelled on the swatch |

### As actually built — logo PDF + profile deck

| Role | Hex | Where |
|---|---|---|
| Green | `#385940` | the logo mark and wordmark, and deck body panels |
| Deep green | `#1C3D2C` – `#2A4E37` | closing page background |
| Gold | `#B6944A` | logo circle and "DIGITAL SOLUTIONS" |
| Cream | `#FFFBEF` / `#FFFDF4` | deck page background |

`#236147` is a cleaner, more saturated green; `#385940` is greyer and softer.
They are visibly different. **Ask the client which one is authoritative** —
if they say "match the logo", the site should use `#385940`.

Working assumption until they answer: build on the logo values, since the logo
is the asset that already exists in the market.

## Type

Not supplied. The deck sets everything in a geometric sans — headings in a
heavy weight, body in regular — consistent with Poppins / Gilroy / Museo Sans,
but no font file or name was given. **TBD — ask the client**, otherwise
Poppins is a safe free stand-in that matches the deck closely.

The wordmark itself is a customised/geometric face with cut terminals (the
`A` has no crossbar). It should always be used as artwork, never re-typed.

## Logo

`brand/adhishtam-logo-primary.pdf` — master file, 135 MB, not in git (see
README). `brand/adhishtam-logo-primary.png` is a 2400 px render of it for
day-to-day use.

The mark is a green peak/chevron `A` inside an open gold ring. Two treatments
appear in the deck:

- **Primary** — green mark + green wordmark + gold "DIGITAL SOLUTIONS", on cream
- **Reversed** — all white, on deep green (closing page)

Still needed for the website: a transparent-background PNG, an SVG, a
favicon-safe mark-only crop, and the white reversed lockup. None of these
exist yet — they'd have to be traced or requested from the client.
